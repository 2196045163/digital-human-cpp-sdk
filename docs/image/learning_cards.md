### 模块：face_detect 

1. 这个模块叫什么？代码类名叫什么？
模块名是 人脸检测模块，代码的类名是 FaceDetector

2. 它解决什么问题？（检测 + 关键点，不做身份识别）
该模块的主要功能是从加载进来的图片中检测人脸框，然后使用 `dlib` 标记人脸的68个五官关键点

3. 输入是什么？输出是什么？
输入是 来自 ImageLoader 的cv::Mat 图像，也就是加载进来的图片
输出是 FaceAnalyzeResult，主要的信息是 人脸框坐标（opencv） + 68 关键点 + 嘴部 20 点 + 状态码 + 耗时

4. 核心数据结构有哪些？（FaceDetectionResult、LandmarkResult 等）
ModelResult、FaceDetectionResult、LandmarkResult、FaceAnalyzeResult

5. 核心流程是什么？（LoadImage → Detect → GetLandmarks → 嘴部点）
检测流程是 从文件/内存中加载图片（LoadImage） -> Detect 检测人脸框 -> GetLandmarks 对人脸框做关键点预测 -> 提取主要嘴部48-67关键点（参考项目是这样的，但是是不是还可以考虑捕捉更多的关键点？）

6. 最容易失败在哪？（坐标转换、小脸、模型路径错误、通道不对）
容易失败的地方有 opencv 的人脸框坐标与dlib人脸框坐标的转换、图片中的人脸太小，dlib检测不到等

7. 怎么验证？（13 组 CTest + example 可视化）
主要就是通过测试代码测试边界情况来验证功能实现

8. 后续哪个模块会调用它？（人脸对齐）
人脸对齐模块 FaceAligner，它需要原图 cv::Mat + 68 点关键点，这就是本模块直接输出的这两个

9. 面试 2 分钟怎么讲？
这个模块我使用 dlib 封装的 HOG+SVM 做人脸检测和 68 点 人脸五官预测，
实现细节主要是使用几个结构体 Result 代替异常、12 个状态码区分错误、Pimpl 隐藏 dlib 依赖、复用 ImageLoader 做图片输入，最后通过 13 组 CTest 自动化测试和可视化 example 做验收。

**人脸框检测流程**：

输入一张图像 → 按照不同的缩放比得到不同尺寸的图像构成图像金字塔 → 使用一个固定大小的检测窗口在每一个图像中扫描 → 在每个检测窗口内，HOG 先计算窗口内每个像素的梯度方向和梯度大小，然后划分 Cell 小块并量化 Cell 小块的边缘方向得到 Cell 的边缘特征向量 → 将多个 Cell 组成一个 Block，Block 在检测窗口内以指定步长滑动，得到多个 Block，并对每个 Block 的边缘特征向量做归一化，减小亮光和暗光下 Block 的梯度大小差异 → SVM 对由多个归一化 Block 组成的整个检测窗口做分类，判断检测窗口内是否有人脸。

SVM 就像一个"安检门"：HOG 提取边缘形状特征，SVM 对特征打分。分数够高 → 框出来。分数不够 → 跳过。`detector(dlib_img, 0)` 这一行封装了以上全部过程。

**人脸关键点定位流程（ERT）**：

先在人脸框里放一个平均脸——68 个点的初始位置，这个平均脸是从几万张训练数据中学出来的。然后 500 棵回归树依次工作：每棵树在每个关键点附近取一对像素，比较它们的亮度差，根据比较结果给出一个具体的偏移量 (dx, dy)——比如往右 0.3px、往上 0.1px。方向和幅度都是训练时从几万张标注人脸中学好的。上一棵树的输出加上这棵树的偏移就是下一棵树的输入，500 棵串起来，逐步把 68 个粗糙的初始点修正到精确的五官位置。

SVM 是粗定位（"脸在哪"），ERT 是精定位（"五官具体在哪"），两件事两个模型前后串在一起。


### 模块：face_aligner_and_image_preprocessor（图像预处理模块）
1. 这个模块叫什么？包含哪两个类？
    这个模块是图像预处理模块，主要包含 FaceAligner 和 ImagePreprocessor 两个类

2. 解决什么问题？（几何对齐 + 像素预处理，拆成了什么？）
    这个模块的功能可以分成两个：
    一是 FaceAligner 类将原始 cv::Mat 图像、人脸框和关键点按照所用模型的要求做统一的几何对齐，包括旋转、缩放、平移；
    二是 ImagePreprocessor 类对已经对齐的人脸框和关键点做像素预处理，包括尺寸修改、颜色顺序修改、数据类型转换以及像素的数值范围确定等，以得到所用模型能够直接使用的标准化输入图像

3. 输入是什么？输出是什么？（两个类各自的输入输出）
    FaceAligner 的输入是 ImageLoader 加载的原始 cv::Mat 图像数据image，FaceDetector 检测得到的人脸框和68个人脸关键点 face_rect 和 landmarks；输出则是得到所用模型要求的统一对齐的人脸图和关键点；
    ImagePreprocessor 的输入是 FaceAligner 对齐之后的人脸；输出则是能直接喂给目标模型的标准化输入图像

4. 核心数据结构有哪些？（FaceAlignmentResult、ImagePreprocessResult 等）
    FaceAlignmentResult、FaceAlignmentOptions、ImagePreprocessResult、ImagePreprocessOptions、ImagePreprocessStatus

5. 核心流程是什么？（从双眼坐标到 96x96 对齐脸，再到归一化的完整链路）
    核心流程：提取输入人脸关键点中的双眼坐标，计算图像中人脸角度等相关参数 -> 计算得到几何对齐的变换矩阵和逆矩阵 -> 对输入的人脸框和关键点用变换矩阵做对齐得到对齐人脸 -> Image_Preprocessor 对对齐之后的人脸做像素预处理，包括尺寸、颜色顺序、数据类型和像素数值范围等 -> 得到能直接喂给模型的标准化输入图像数据。

6. 最容易失败在哪？（双眼退化、坐标混用、矩阵类型不匹配、归一化公式写错）
    容易失败的地方在，图像中人脸的双眼不明显检测不清晰；
    在原图坐标系变换得到对齐后的人脸坐标系之后，Image_Preprocessor 仍旧处理原图中的人脸而不是对齐之后的人脸等；

7. 怎么验证？（4 个 CTest 共 40+ 组测试 + 两个 example 可视化）
    已经做了完整的单元测试和模块测试

8. 后续哪个模块会调用它？（mask 融合 + InputProcessor）
    后面的人脸掩码融合模块以及输入处理器会用到

9. 面试 2 分钟怎么讲？
    当前这个模块是图像预处理模块，主要的功能就是对图像中的人脸按照所用模型的要求最几何对齐和像素的预处理，最后得到能直接喂给模型的标准化图像数据；其中几何对齐只是以人脸双眼中心为几何中心做旋转、缩放和平移，像素预处理则是对已经对齐的人脸做图像的尺寸做调整、像素的颜色顺序做变换、数值类型做转换以及确定像素的数值范围

### 模块：face_mask_generator

1. 这个模块叫什么？代码类名叫什么？
    人脸掩码生成模块，FaceMaskGenerator
2. 解决什么问题？
    为人脸图的目标区域（当前 Wav2Lip 模型是嘴部关键点围成的区域）生成掩码，指示模型融合生成目标区域的像素

3. 输入是什么？输出是什么？
    输入：输入是图像的尺寸、人脸关键点、掩码生成的相关选项
    输出：一张和输入同尺寸的灰度图（CV_32FC1，0~1）和一个包含了这个模块处理的状态信息和这张图片统计信息以及模块所用参数的结构体

4. 核心数据结构有哪些？
    FaceMaskStatus（7 个状态码）、FaceMaskOptions（嘴部模式/凸包开关/膨胀半径/模糊核/边界清零等）、FaceMaskInfo（宽高/类型/min/max/non_zero_count）、FaceMaskResult（success/status/alpha_mask/info/options_used）

5. 核心流程是什么？（关键点 → 凸包 → 填白 → 膨胀 → 羽化 → 归一化）
    模块的处理流程实际就是：输入图像尺寸、人脸关键点坐标和处理选项 -> 根据关键点坐标画凸包，这样生成的张嘴闭嘴动作更稳定 -> 把凸包填白 -> 凸包的白色区域根据处理选项中的参数做膨胀，避免生成张嘴动做时凸包外的像素点被截断 -> 羽化，即高斯模糊，以凸包中心为核心，逐步向其周围像素点分配像素点值，让像素点的值缓慢变化，这样模型生成核融合出来的图像边缘会更加柔和 -> 像素值的点归一化，即像素点值都变为 0-1；期间实际还有两次清理边沿的动作，分别在膨胀和羽化之后，避免在把生成和融合的图像贴回原图时出现黑色边框。

6. 最容易失败在哪？（坐标混用、Point2f 未转 Point、bbox 越界）
    i. 原图尺寸和对齐图的关键点混用；
    ii. 关键点坐标在对齐图坐标系下是Point2f类型，但是 cv::fillConvexPoly 只处理整形，所以需要转换
    iii. 由于 膨胀把白区向外推了，如果图像尺寸太小，就容易让白区覆盖到下巴，鼻子等地方，模型却只生成嘴部的画，这些嘴部之外的地方就会被低分辨率的像素替代，让图像看上去很糊

7. 怎么验证？（17 组 CTest + 7 张 example 调试图）
    单元测试用合成关键点（不依赖 dlib 模型）覆盖：正常掩码生成、空尺寸报错、关键点不足报错、参数负数校验、偶数模糊核自动修正、数值范围始终 0~1、三通道转换等。example 输出 7 张调试图肉眼确认掩码位置和融合效果。

8. 后续哪个模块会调用它？
    人脸融合模块会用到本模块输出的灰度图，并配合 M_inv 贴回原图

9. 面试 2 分钟怎么讲？
    我在人脸对齐之后实现了一个嘴部 掩码 生成模块。它输入 68 点关键点，通过凸包填白、形态学膨胀、高斯羽化和边界清理，在 96x96 对齐坐标系中输出 一张灰度图。该 灰度图的像素值 用融合公式 out = gen × mask + orig × (1-mask) 计算得到，后续配合 M_inv 把结果贴回原图。我用结构化 Result 返回错误、用合成的关键点做了 17 组单元测试、用 example 模块测试输出 7 张调试图做可视化验证。特别地，mask 实际上就是 cv::Mat 类型的数据
